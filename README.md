# დაკვირვების ხარისხის კონტროლის სისტემა (Zoommer)

თანამშრომელთა მიერ მომხმარებელზე დაკვირვებისას გაკეთებული აუდიო ჩანაწერების და ხელით ატვირთული ზარების მართვის სისტემა როლების მიხედვით (ადმინისტრატორი / მენეჯერი / თანამშრომელი), Google Gemini-ის საშუალებით ავტომატური შეფასებით მორგებადი კრიტერიუმების მიხედვით.

## გაშვება ლოკალურად

საჭიროა [Node.js](https://nodejs.org) **ვერსია 22.5 ან უფრო ახალი** (მონაცემთა ბაზა იყენებს Node-ის ჩაშენებულ SQLite მოდულს — დამატებითი კომპილატორი, Python თუ Visual Studio Build Tools არ სჭირდება).

```bash
npm install
npm start
```

გაშვებისას ტერმინალში შეიძლება გამოჩნდეს ერთი გაფრთხილება — `ExperimentalWarning: SQLite is an experimental feature` — ეს ნორმალურია და არაფერზე არ მოქმედებს.

სერვერი გაეშვება მისამართზე: **http://localhost:3000**

პირველი გაშვებისას ტერმინალში დაბეჭდილი იქნება საწყისი ადმინის ანგარიშის მონაცემები:

```
მომხმარებელი: admin
პაროლი:       admin123
```

**პირველივე შესვლისას აუცილებლად შეცვალეთ პაროლი** (მენიუ „პარამეტრები“ → „ჩემი პაროლის შეცვლა“).

## GEMINI API-ის დაკავშირება

1. შედით სისტემაში ადმინის ანგარიშით.
2. გადადით „პარამეტრები“-ში.
3. ჩასვით თქვენი Gemini API გასაღები („GEMINI API კონფიგურაცია“) და შეინახეთ.
4. სურვილისამებრ შეცვალეთ მოდელის სახელი (ნაგულისხმევია `gemini-2.5-flash`).

გასაღები ინახება მხოლოდ ლოკალურად, სერვერის SQLite ბაზაში (`data/app.db`) — არსად არ იგზავნება Zoommer-ის გარეთ, გარდა Gemini API-ის მოთხოვნისა თავად შეფასებისას.

## რას მოიცავს სისტემა

- **როლების მართვა**: ადმინისტრატორი, მენეჯერი, თანამშრომელი — თითოეულს განსხვავებული უფლებები (მენიუ „თანამშრომლები და როლები“, მხოლოდ ადმინისტრატორისთვის).
- **დაკვირვების ჩაწერა**: თანამშრომელი მობილურიდან ან კომპიუტერიდან იწყებს/ასრულებს აუდიო ჩანაწერს პირდაპირ ბრაუზერიდან (მიკროფონის საშუალებით), მიუთითებს ფილიალს და შენიშვნას.
- **ზარის ხელით ატვირთვა**: ადმინისტრატორი/მენეჯერი ატვირთავს უკვე არსებულ აუდიო ფაილებს (ერთს ან რამდენიმეს ერთბაშად).
- **შეფასების კრიტერიუმები**: შეუზღუდავი რაოდენობის შაბლონის შექმნა, თითოეულში საკუთარი კრიტერიუმებით და მაქსიმალური ქულებით. შეფასებისას შესაძლებელია რამდენიმე შაბლონის ერთდროულად შერჩევა — ყველა კრიტერიუმი გაერთიანდება ერთ შეფასებაში.
- **AI შეფასება**: აუდიო იგზავნება Gemini-სთან, უბრუნდება ტრანსკრიფცია, თითოეულ კრიტერიუმზე ქულა და დასაბუთება, და საერთო შეჯამება. ნაგულისხმევად ახალი ჩანაწერი **არასდროს** იგზავნება ავტომატურად — შეფასებას იწყებთ მხოლოდ ხელით, ჩანაწერის დეტალებში, სასურველი შაბლონ(ებ)ის არჩევით. თუ გნებავთ, „პარამეტრები“-დან შეგიძლიათ ჩართოთ ავტომატური რეჟიმი (და ნებისმიერ დროს ისევ გამორთოთ) — მაშინ ყოველი ახალი ჩანაწერი დაუყოვნებლივ დამუშავდება წინასწარ შერჩეული შაბლონ(ებ)ით, ხოლო ხელით შეფასების ღილაკი ყოველთვის ხელმისაწვდომია, კონკრეტული ჩანაწერის ცალკე დასამუშავებლად.
- **ჩანაწერების რეესტრი**: ფილტრაცია თარიღით, ფილიალით, თანამშრომლით და სტატუსით; დაკვრა/ჩამოტვირთვა; დეტალური შეფასების ნახვა. შეფასებული ჩანაწერის დეტალურ ხედში ღილაკი „PDF-ად გადმოწერა“ ხსნის ბეჭდვისთვის მომზადებულ გვერდს (ბრაუზერის „Save as PDF“-ით ინახება).
- **ფოტოების საქაღალდე**: ჩანაწერის დეტალურ ხედში შეგიძლიათ ატვირთოთ ერთი ან რამდენიმე ფოტო (დაკვირვებისას გადაღებული სურათები და ა.შ.), ნახოთ მინიატურების სახით და წაშალოთ საჭიროებისამებრ. ეს ფოტოები ავტომატურად ერთვის „PDF-ად გადმოწერა“-ს შედეგშიც.
- **ანალიტიკა** (ადმინისტრატორი/მენეჯერი): შეფასებების დინამიკის გრაფიკი დღეების მიხედვით, ფილიალების შედარება საშუალო ქულით, კრიტერიუმების რეიტინგი (ყველაზე სუსტიდან), და თითოეული ფილიალის ძლიერი/სუსტი მხარეები — ყველა ფილტრდება თარიღითა და ფილიალით.

## გარე სისტემიდან ჩანაწერების იმპორტი (API)

თუ გყავთ საკუთარი Python (ან სხვა ენის) სკრიპტი, რომელიც აწარმოებს ხმის
ჩანაწერებს და მათ ტრანსკრიფციას (მაგ. საკუთარი voice-recording/
transcription პაიფლაინი), შეგიძლიათ ისინი ავტომატურად შეიტანოთ ამ
პლატფორმაზე REST API-ის საშუალებით — პლატფორმა შემდეგ Gemini-ით
ჩაატარებს შეფასებას მოწოდებული ტრანსკრიფციის მიხედვით (აუდიო არ
იგზავნება ხელახლა გასატრანსკრიფცირებლად, მხოლოდ შესაფასებლად საჭირო
ტექსტი).

**გასაღების მიღება**: „პარამეტრები“ → „API იმპორტის გასაღები“ →
„ახალი გასაღების გენერაცია“ (მხოლოდ ადმინისტრატორისთვის). გასაღები
გამოჩნდება მხოლოდ ერთხელ — დააკოპირეთ და შეინახეთ თქვენს სკრიპტში
(გარემოს ცვლადში, არა კოდში პირდაპირ).

**Endpoint**: `POST /api/import/recording`
**ავთენტიკაცია**: HTTP header `X-API-Key: <გასაღები>`
**ფორმატი**: `multipart/form-data`

| ველი | სავალდებულო | აღწერა |
|---|---|---|
| `audio` | კი | აუდიო ფაილი (mp3/wav/m4a/aac/ogg/flac/webm/opus/aiff) |
| `transcript` | კი | უკვე მზა ტრანსკრიფცია — ტექსტი, რომელსაც Gemini პირდაპირ შეაფასებს |
| `employee_name` | არა | თანამშრომლის სრული სახელი თავისუფალ ტექსტად (მაგ. „გიორგი გიორგაძე“). შედარდება პლატფორმაზე უკვე არსებულ თანამშრომლებთან სახელით — რეგისტრზე და ზედმეტ spaces-ზე დამოუკიდებლად |
| `branch_name` | არა | ფილიალის სახელი თავისუფალ ტექსტად (მაგ. „თბილისი“), იგივე პრინციპით |
| `employee_id` / `branch_id` | არა | თუ იცით პლატფორმის შიდა რიცხვითი ID, შეგიძლიათ პირდაპირ მიუთითოთ სახელის ნაცვლად |
| `note` | არა | თავისუფალი შენიშვნა |
| `recorded_at` | არა | ჩანაწერის რეალური თარიღი/დრო ISO ფორმატში (თუ არ მიუთითეთ — გამოიყენება ატვირთვის მომენტი) |
| `template_ids` | არა | კონკრეტული შეფასების შაბლონების ID-ების სია JSON მასივად (მაგ. `[1,2]`). თუ არ მიუთითეთ — გამოიყენება „პარამეტრები“-ში დაყენებული ავტომატური შეფასების ნაგულისხმევი შაბლონები |

**სახელით ძებნა**: თუ მითითებული `employee_name`/`branch_name` ვერ
მოიძებნა ზუსტი დამთხვევით, ჩანაწერი მაინც ინახება (თანამშრომლის/
ფილიალის გარეშე), თუმცა ამის შესახებ ავტომატურად ემატება შენიშვნა
ჩანაწერზე — შემდეგ პლატფორმაზე ხელით შეგიძლიათ მიაბათ სწორ ჩანაწერს.

**პასუხი** (მაშინვე, შეფასების დაწყებამდე):
```json
{ "id": 42, "employee_matched": true, "branch_matched": true }
```
შეფასება მუშავდება ფონურად — ჩანაწერის სტატუსი პლატფორმაზე გადავა
`დამუშავებაში → შეფასებული` (ან `შეცდომა`, თუ Gemini-ის გასაღები არ
არის კონფიგურირებული).

მუშა მაგალითი Python-ზე: [`examples/import_recording.py`](examples/import_recording.py).

## მონაცემების შენახვის ადგილმდებარეობა

- ბაზა: `data/app.db` (SQLite)
- აუდიო ფაილები: `data/recordings/`

ამ საქაღალდის რეგულარულად დაბექაფება რეკომენდებულია.

## გაშვება Render-ზე (GitHub-იდან ავტომატური დეპლოი)

1. ატვირთეთ ამ საქაღალდის ფაილები (`node_modules` და `data` გარეშე) GitHub-ის private repo-ში.
2. Render → **New → Blueprint** → აირჩიეთ ეს repo. `render.yaml` თავად შექმნის სერვისს და მუდმივ დისკს (`/var/data`) — დისკი ფასიან გეგმას (Starter) მოითხოვს, რადგან უფასო გეგმაზე ფაილები ყოველ დეპლოიზე იშლება.
3. პირველ შესვლაზე: `admin` / `admin123` → დაუყოვნებლივ შეცვალეთ პაროლი.
4. არსებული მონაცემების გადასატანად: ძველ სისტემაში „პარამეტრები → ბექაფის ჩამოტვირთვა“, ახალში „პარამეტრები → აღდგენა“. ბექაფი შეიცავს გასაღებებსაც — GitHub-ზე არასდროს ატვირთოთ.
5. შემდეგი განახლებები: ფაილის შეცვლა GitHub-ზე → Render ავტომატურად გაუშვებს ახალ ვერსიას, მონაცემები დისკზე ხელუხლებელი რჩება.

## რეალურ სერვერზე გადატანა

1. გადაიტანეთ მთელი პროექტის საქაღალდი (`data/`-ის გარეშე, თუ გსურთ სუფთა დაწყება, ან მასთან ერთად, თუ გსურთ არსებული მონაცემების შენარჩუნება).
2. სერვერზე გაუშვით `npm install --omit=dev` და შემდეგ `npm start`, ან გამოიყენეთ პროცესის მენეჯერი (მაგ. [PM2](https://pm2.keymetrics.io)) მუდმივი მუშაობისთვის: `pm2 start server.js --name observation-qa`.
3. დააყენეთ HTTPS reverse proxy (Nginx/Caddy) სერვერის წინ — ავტორიზაციის cookie-ები დაცული უნდა იყოს.
4. სასურველია გარემოს ცვლადით მიუთითოთ პორტი: `PORT=3000 npm start`.
5. Gemini API გასაღები ხელახლა შეიყვანეთ „პარამეტრები“-დან ახალ სერვერზეც (ის ბაზასთან ერთად გადადის, თუ `data/`-საც გადაიტანთ).

## ცნობილი შეზღუდვები (MVP ვერსია)

- ავტორიზაცია დაფუძნებულია JWT ქუქიზე; სესიის გასაუქმებლად საჭიროა ბრაუზერიდან ქუქის წაშლა ან პაროლის შეცვლა.
- აუდიო ხანგრძლივობა დაკვირვების ჩანაწერებისთვის იზომება ბრაუზერში; ხელით ატვირთვისას არ არის ავტომატურად გამოთვლილი.
- დიდი აუდიო ფაილები (20MB-ზე მეტი) იტვირთება Gemini Files API-ის საშუალებით ავტომატურად — დამატებითი კონფიგურაცია არ სჭირდება.
